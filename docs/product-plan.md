# App-Q Product Plan

## Product Definition

App-Q is a synthetic persona research assistant for the Turkish market. It helps founders, agencies, product teams, and growth marketers test product concepts before committing budget.

## Core User Flow

1. User enters a research brief.
2. App-Q identifies missing information and asks focused questions.
3. App-Q creates a balanced persona panel.
4. Each persona is interviewed in isolation.
5. The synthesis engine produces evidence-linked findings.
6. The user receives a structured report with hypotheses, objections, price sensitivity, and next actions.

## MVP Scope

- Brief intake
- Clarifying questions
- Persona generation
- Isolated interview simulation
- Evidence-linked synthesis
- Markdown report output
- Model-provider abstraction
- Local operator mode with sequential persona interviews
- Streamlit UI for the first hands-on workflow

## Out of Scope for MVP

- Fine-tuning
- Payment system
- Multi-tenant user management
- Live respondent recruitment
- Statistical confidence claims
- Automated scraping of personal or copyrighted data

## Learning Loop Requirement

App-Q must be designed so it can improve after launch using approved real usage data. The first phase should collect feedback for evaluation, not fine-tuning. Fine-tuning becomes appropriate only after enough consented, anonymized, high-quality examples exist.

## Positioning

App-Q should be positioned as a hypothesis and research triage tool. It should reduce wasted time and budget before real market testing, not claim to replace real customer research.

## Target Segments

- Strategy and creative agencies
- B2B SaaS product teams
- E-commerce founders
- Growth marketers
- Product managers testing positioning, messaging, and pricing

## First Commercial Motion

The first realistic go-to-market path is a productized research service rather than a self-serve SaaS platform. The operator runs App-Q locally, delivers a structured report, and uses privacy-preserving local execution as a differentiator.
